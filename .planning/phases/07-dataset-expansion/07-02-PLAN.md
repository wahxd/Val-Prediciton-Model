Valoscribe CLI commands (all at D:\Git\valoscribe, run via `python -m valoscribe`):

1. `valoscribe scrape-vlr <match_url> -o match_data.json`
   - Scrapes VLR.gg match page, outputs JSON with teams, maps, VOD URLs, players, agents

2. `valoscribe split-metadata <series_metadata.json> --output-dir ./maps/`
   - Splits series metadata into per-map metadata files (map1.json, map2.json, etc.)

3. `valoscribe download <youtube_url> --output ./videos/ --start <seconds> --duration <seconds>`
   - Downloads YouTube video via yt-dlp with optional timestamp trimming

4. `valoscribe orchestrate process-vod <video_path> <metadata_path> --output <output_dir> --quiet`
   - Processes VOD through GameStateManager, outputs events.jsonl + frames.csv

Processing flow per match:
  scrape-vlr -> split-metadata -> for each map: download -> process-vod -> delete video

Key constraints from CONTEXT.md:
- Sequential processing (one VOD at a time)
- Delete VOD files after successful processing
- Output to separate directory from existing 71 maps
- Must be resumable
- Manifest tracks everything
</context>

2. Create src/scraping/orchestrator.py with VODOrchestrator class:

   __init__(self, config: ProcessingConfig, manifest: ProcessingManifest):
     Store config and manifest. Set up structlog logger.

   _run_valoscribe_cmd(self, args: list[str], timeout: int | None = None, cwd: Path | None = None) -> subprocess.CompletedProcess:
     - Runs: python -m valoscribe {args}
     - Sets cwd to config.valoscribe_repo
     - Uses subprocess.run with check=True, capture_output=True, text=True, timeout
     - Logs command, exit code, and truncated stderr on failure
     - Raises subprocess.CalledProcessError on failure

   scrape_and_populate(self, event_url: str, tournament_name: str) -> int:
     - Uses VLREventScraper from Plan 01 to discover match URLs
     - For each match URL: calls `valoscribe scrape-vlr <match_url> -o <metadata_dir>/<match_id>.json`
     - Parses the output JSON to extract per-map data
     - Creates VODRecord entries in manifest for each map that has a VOD URL
     - Returns count of new VODs added
     - Rate limits between scraping calls (1.5 second delay)

   process_single_vod(self, record: VODRecord) -> bool:
     - Returns True on success, False on failure
     - Steps:
       a. Update status to "downloading", save manifest
       b. Download VOD: call `valoscribe download <youtube_url> --output <download_dir>`
          - Find the downloaded file (Valoscribe names it based on video title)
       c. Get per-map metadata: the scrape step already saved series JSON.
          - Call `valoscribe split-metadata <series_json> --output-dir <metadata_dir>/maps/`
          - Use the correct map metadata file (map{N}.json)
       d. Update status to "processing", save manifest
       e. Process VOD: call `valoscribe orchestrate process-vod <video_path> <metadata_path> --output <output_dir>/<vod_id>/ --quiet`
       f. Update status to "complete" with map_id, completed_at, processing_time_seconds
       g. Delete downloaded VOD file (if config.delete_vod_after_processing)
     - On failure: update status to "failed" with error_message, increment retry_count
     - On timeout: same as failure but note timeout in error_message
     - Always clean up VOD file in finally block
     - Add download_delay_seconds sleep between VODs (YouTube rate limiting)

   IMPORTANT IMPLEMENTATION DETAIL: Since Valoscribe's scrape-vlr already produces series-level JSON with per-map VOD URLs, the orchestrator should:
   1. Call scrape-vlr once per match (saves series JSON)
   2. Call split-metadata once per match (creates per-map metadata files)
   3. For each map: download the specific map's VOD URL, then process-vod with that map's metadata

   For VOD downloading: the VLR scraper extracts per-map YouTube URLs (timestamped links to specific maps within a series VOD). Valoscribe's download command handles timestamp extraction from the URL's t= parameter.

   run_pipeline(self) -> dict:
     - Main processing loop
     - Gets all pending VODs from manifest
     - For each pending VOD: call process_single_vod
     - Skip VODs that have failed more than max_retries times (update to "skipped")
     - Log progress every VOD: "Processing X/Y (Z complete, W failed)"
     - Return summary dict (same format as manifest.get_summary())

   - Standalone CLI script (no typer/click dependency, use argparse from stdlib)
   - Adds project root and Valoscribe src to sys.path so imports work
   - Arguments:
     - event_url (positional, optional): VLR.gg event URL to discover VODs from
     - --manifest: Path to manifest file (default: data/processing/manifest.json)
     - --output-dir: Output directory for processed data (default: data/processing/processed)

     - --valoscribe-repo: Path to Valoscribe repo (default: D:\Git\valoscribe or EXPANSION_VALOSCRIBE_REPO env var)

     ```
     # Discover + process VODs from Masters Bangkok
     python scripts/expand_dataset.py "https://www.vlr.gg/event/matches/2094/masters-bangkok/"

     # Only discover VODs (queue for later processing)
     python scripts/expand_dataset.py "https://www.vlr.gg/event/matches/2094/masters-bangkok/" --discover-only

     # Resume processing (no discovery, just process pending)
     python scripts/expand_dataset.py --process-only

     # Check what's in the manifest
     python scripts/summarize_progress.py
     ```
