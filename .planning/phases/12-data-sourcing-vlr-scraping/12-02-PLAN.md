    Create `src/scraping/vlr_match_scraper.py` with class `VLRMatchScraper`:

    **Purpose:** Parse already-fetched VLR.gg match page HTML to extract rich metadata that Valoscribe's scrape_match does NOT extract (player stats, player VLR IDs).

    **Constructor:** `__init__(self, team_normalizer: TeamNormalizer)`

    **Method: parse_match(html: str, match_url: str) -> dict**
    Parse a VLR.gg match page (game=all view) and return:
    ```python
    {
        "match_url": str,
        "teams": [str, str],  # normalized team names
        "match_score": str,   # "2-1" format
        "date": str,          # ISO YYYY-MM-DD from match header
        "maps": [
            {
                "map_number": int,
                "map_name": str,
                "map_score": str,   # "13-9" format
                "vod_url": str | None,  # YouTube URL from VLR page (may be None)
                "starting_sides": {"team1": "attack"|"defense", "team2": ...},
                "agent_compositions": [{"name": str, "team": str, "agent": str}, ...],
                "player_stats": {
                    "player_name": {
                        "acs": float,
                        "kills": int,
                        "deaths": int,
                        "assists": int,
                        "kast_pct": float | None,  # May not be present for older matches
                        "adr": float,
                        "hs_pct": float,
                        "fk": int,
                        "fd": int,
                    }
                },
                "player_vlr_ids": {"player_name": int},
            }
        ]
    }
    ```

    **Extraction strategy for player stats:**
    - VLR.gg stat tables use `<table class="wf-table-inset mod-overview">` for each team per map
    - Columns (in order): Player, Agents, R (rating?), ACS, K, D, A, +/-, KAST%, ADR, HS%, FK, FD
    - Parse each `<tr>` row: extract player name from `<td>` with player link, agent from `<img title="">`, stats from remaining `<td>` cells
    - Handle missing/empty cells gracefully (return None for missing values)
    - The first 2 tables are "All Maps" aggregate stats. Per-map tables start at index 2 (same pattern as Valoscribe: `(container_index + 1) * 2`)

    **Player VLR.gg ID extraction:**
    - Player links have format: `<a href="/player/{ID}/{name}">` within stat table rows
    - Use regex to extract numeric ID from href
    - Build player_vlr_ids dict mapping player display name to VLR ID

    **Date extraction:**
    - Look for match header date element (class containing "moment-tz-convert" or date text in match header area)
    - Parse to ISO YYYY-MM-DD format. If not found, return empty string.

    **Match score extraction:**
    - From match header: look for score elements (the big "2" : "1" display)
    - Format as "2-1" string

    **Map score extraction:**
    - From each map's game header: extract the per-map score (e.g., "13-9")

    **VOD URL extraction:**
    - Reuse Valoscribe's approach: look in `match-streams-bets-container` for "Map N" YouTube links
    - This is a fallback; Plan 03 will handle YouTube API search as primary source

    **Agent and starting side extraction:**
    - Reuse the same HTML structure approach as Valoscribe VLRScraper._extract_players and _extract_starting_sides
    - Agent from `<img title="agent_name">` in stat tables
    - Starting sides from vlr-rounds timeline (first round winner + side classes)

    **Important:** Use BeautifulSoup + lxml. Parse the HTML string directly (no HTTP requests in this class). HTTP fetching is handled by VLREventScraper.

    **Tests** (`tests/scraping/test_vlr_match_scraper.py`):
    - Create a minimal but realistic HTML fixture string representing a VLR.gg match page with 2 maps, stat tables, player links, round timeline. (Approximately 100-150 lines of HTML - just enough to test selectors.)
    - Test parse_match extracts correct team names
    - Test parse_match extracts player_stats with expected keys (acs, kills, deaths, etc.)
    - Test parse_match extracts player_vlr_ids from player links
    - Test parse_match extracts agent_compositions
    - Test parse_match handles missing stat cells gracefully (no crash, None values)
    - Test parse_match extracts match_score and map_score
