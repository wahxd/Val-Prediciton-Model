  <name>Task 1: Quality scoring module -- per-map quality signals and tiered scoring</name>
  <files>src/data/quality.py</files>
  <action>
    Create `src/data/quality.py` with:

    **Data classes:**
    - `QualityCheck` (dataclass):
      - `name: str` (e.g., "kill_count", "round_progression")
      - `score: float` (0.0-1.0)
      - `weight: float` (contribution to overall score)
      - `issues: list[str]`
      - `warnings: list[str]`
      - `details: dict[str, Any]` (signal-specific details for the audit report)

    - `QualityScore` (dataclass):
      - `map_id: str`
      - `overall_score: float` (0.0-1.0, weighted average of checks)
      - `tier: Literal["high", "medium", "low"]`
      - `checks: list[QualityCheck]`
      - `valoscribe_validation: dict[str, Any] | None` (from metadata.json)
      - `cross_check_disagreements: list[str]` (where our checks disagree with Valoscribe's)
      - `all_issues: list[str]` (aggregated from all checks)
      - `all_warnings: list[str]` (aggregated from all checks)
      - `flagged_for_review: bool` (True if tier is "low" or has disagreements)

    **Quality check functions** (each returns a QualityCheck):

    1. `check_kill_count(events, metadata) -> QualityCheck`:
       - Count kill events
       - A standard Valorant map has ~150-300 kills (13-24 rounds, ~10-15 kills/round)
       - Score: 1.0 if kills >= 100, scale linearly from 0.0 at 0 kills to 1.0 at 100
       - Issue if < 50 kills ("Critically low kill count: {n}")
       - Warning if < 100 kills ("Below expected kill count: {n}")
       - Details: {"kill_count": n, "expected_min": 100, "expected_max": 300}
       - Weight: 0.25

    2. `check_round_progression(events) -> QualityCheck`:
       - Extract round numbers from round_start and round_end events
       - Check: round numbers should be sequential (1, 2, 3, ..., N)
       - Check: for each round, there should be both a round_start and a round_end
       - Score: 1.0 if perfect, deduct proportionally for gaps/missing events
       - Issue for non-sequential rounds, missing round starts/ends
       - Details: {"total_rounds": n, "missing_starts": [...], "missing_ends": [...], "gaps": [...]}
       - Weight: 0.25

    3. `check_round_start_end_balance(events) -> QualityCheck`:
       - Count round_start events vs round_end events
       - They should be equal (or round_start = round_end + 1 if last round incomplete)
       - Score: 1.0 if balanced, 0.5 if off by 1, lower for bigger imbalance
       - Details: {"round_starts": n, "round_ends": m, "difference": abs(n-m)}
       - Weight: 0.15

    4. `check_event_completeness(events) -> QualityCheck`:
       - Group events by round number
       - Per round, expect: at least 1 round_start/round_end and at least 1 kill
       - Score: proportion of rounds that have all expected event types
       - Warning for rounds with no kills ("Round {r} has no kill events -- possible OCR gap")
       - Details: {"rounds_checked": n, "complete_rounds": m, "incomplete_rounds": [...]}
       - Weight: 0.20

    5. `check_timing_consistency(events) -> QualityCheck`:
       - Timestamps should be monotonically non-decreasing within each round
       - Time between consecutive round_start events should be reasonable (30-300 seconds; Valorant rounds are ~45s buy + up to 100s round)
       - Score: 1.0 if all timing checks pass, deduct for violations
       - Issue for timestamp regression (later event has earlier timestamp)
       - Warning for suspiciously short rounds (<30s) or long gaps (>300s between rounds)
       - Details: {"timestamp_regressions": n, "short_rounds": [...], "long_gaps": [...]}
       - Weight: 0.15

    **Main scoring function:**
    `score_map_quality(events: list[ValoscribeEvent], metadata: MapMetadata | None = None) -> QualityScore`:
    - Run all 5 checks
    - Calculate weighted overall score
    - Determine tier: high (>= 0.8), medium (>= 0.5), low (< 0.5)
    - Cross-check with Valoscribe's validation_results if metadata provided:
      - If Valoscribe says pass but our score is "low" -> add disagreement
      - If Valoscribe says fail but our score is "high" -> add disagreement
    - Set flagged_for_review if tier == "low" or any disagreements exist
    - Return QualityScore

    **Important:** Maps are flagged for review, NOT auto-excluded. With only 71 maps, the user decides per-map. This is a LOCKED decision from CONTEXT.md.

    **Part A: Create `src/data/catalog.py`:**

    Purpose: Auto-discover and document all event types, fields per type, value ranges, and completeness stats across the dataset. Fulfills CONTEXT.md requirement: "Auto-generate a data catalog: all event types found, all fields per event type, value ranges, completeness stats."

    - `FieldStats` (dataclass):
      - `name: str`
      - `dtype: str` (observed Python type: "str", "int", "float", etc.)
      - `count: int` (how many events have this field)
      - `null_count: int` (how many events have this field as None/missing)
      - `unique_values: set[str] | None` (for string fields with < 50 unique values, None otherwise)
      - `min_value: float | None` (for numeric fields)
      - `max_value: float | None` (for numeric fields)
      - `sample_values: list[Any]` (first 5 unique values seen)

    - `CatalogEntry` (dataclass):
      - `event_type: str`
      - `count: int` (total events of this type)
      - `fields: dict[str, FieldStats]`

    - `DataCatalog` class:
      - `entries: dict[str, CatalogEntry]` -- keyed by event type
      - `total_events: int`
      - `total_maps: int`
      - `add_event(event: ValoscribeEvent)` -- accumulate stats from a single event. Extract known fields + model_extra fields. Update counts, types, ranges, unique values.
      - `add_map_events(events: list[ValoscribeEvent])` -- bulk add, increment total_maps
      - `to_dict() -> dict` -- serialize catalog for JSON output
      - `summary() -> str` -- human-readable summary string (event types found, total events, etc.)
