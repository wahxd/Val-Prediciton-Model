  <action>
    **Part A: Create `src/data/audit.py`:**

    - `AuditResult` (dataclass):
      - `timestamp: str` (ISO format)
      - `total_maps: int`
      - `maps_loaded: int`
      - `maps_failed: int`
      - `quality_scores: dict[str, QualityScore]` (map_id -> score)
      - `load_failures: dict[str, str]` (map_id -> error message)
      - `catalog: DataCatalog`
      - `map_index: list[dict]`
      - `tier_summary: dict[str, int]` ({"high": N, "medium": M, "low": K})

    - `run_audit(load_results: dict[str, LoadResult]) -> AuditResult`:
      - For each successful LoadResult, run `score_map_quality()`
      - Build DataCatalog by feeding all events from all maps
      - Build map index via `get_map_index()`
      - Compute tier_summary
      - Return AuditResult

    - `generate_json_report(audit: AuditResult, output_path: Path) -> Path`:
      - Serialize AuditResult to JSON
      - Include: timestamp, tier_summary, map_index, per-map quality scores (with all check details), load failures, catalog (all event types + fields)
      - Write to `output_path / f"audit_{timestamp}.json"`
      - Return the file path

    - `generate_markdown_report(audit: AuditResult, output_path: Path) -> Path`:
      - Single Markdown file with sections:
        1. **Header**: "Valoscribe Data Quality Audit Report", generation timestamp
        2. **Executive Summary**: total maps, tier counts with percentages, dataset readiness assessment, load failure count
        3. **Data Catalog Summary**: table of event types found, count per type, field count per type
        4. **Summary Table**: all maps in a table with columns: map_id, teams, map_name, quality tier, overall score, event count, kill count, round count, issue flags, final score (from round_end events). Sorted by quality score descending.
        5. **Load Failures**: table of failed maps with error messages
        6. **Cross-Check Disagreements**: section listing maps where our quality score disagrees with Valoscribe's validation_results
        7. **Per-Map Details** (one section per map, sorted by map_id):
           - Overall score, tier, component scores table
           - Issues and warnings lists
           - Round-by-round breakdown table: round number, events in round (count by type), issues detected in that round, timing info
           - Files found for this map
      - Table of contents linking to each per-map section
      - Write to `output_path / f"audit_{timestamp}.md"`
      - Return the file path

    - `generate_audit(load_results: dict[str, LoadResult], output_dir: Path) -> tuple[Path, Path]`:
      - Convenience function: run_audit() + generate both reports
      - Create output_dir if not exists
      - Return (json_path, md_path)

    **Part B: Create `src/data/cli.py`:**

    Typer app with commands:

    1. `load` command:
       - Options: `--data-dir` (Path, optional override), `-v`/`--verbose` (bool)
       - Loads all maps, prints summary (success/failure counts, map index table)
       - Uses Rich for progress bar

    2. `audit` command:
       - Options: `--data-dir`, `--output-dir` (default: data/audit), `-v`/`--verbose`
       - Loads all maps + runs full audit + generates both reports
       - Prints paths to generated reports
       - Shows executive summary in terminal

    3. `catalog` command:
       - Options: `--data-dir`, `-v`/`--verbose`
       - Loads all maps, generates data catalog only
       - Prints catalog summary to terminal (event types, field counts, etc.)

    CLI implementation notes:
    - Use `get_config(data_dir_override=data_dir)` for config resolution
    - Use `rich.progress.track()` for per-map progress display
    - Use `rich.console.Console()` for formatted output
    - Use `rich.table.Table` for displaying summary tables in terminal
    - Entry point: `python -m src.data.cli` (add `if __name__ == "__main__": app()`)

    **Part C: Create `data/audit/.gitkeep`:**
    - Empty file to ensure the audit output directory is tracked in git (actual reports are gitignored)

    **Important:** The Markdown report should feel like a data quality dashboard per CONTEXT.md: scan the summary table, drill into per-map round-by-round breakdowns for flagged maps.
