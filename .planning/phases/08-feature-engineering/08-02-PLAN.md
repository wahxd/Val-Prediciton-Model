    Create `src/features/extractors/` package and `round_features.py` module.

    Create `extract_round_features(events: list[ValoscribeEvent]) -> list[RoundFeatures]` function that processes all events for a single map and returns per-round feature records.

    `RoundFeatures` dataclass fields:
    - round_number: int
    - winning_team: str
    - score_team1: int (cumulative after round)
    - score_team2: int (cumulative after round)
    - score_differential: int (team1 - team2, positive = team1 leading)
    - spike_planted: bool (was spike planted this round)
    - spike_defused: bool (was spike defused this round)
    - kills_team1: int (kills by team1 this round)
    - kills_team2: int (kills by team2 this round)
    - kill_differential: int (team1_kills - team2_kills)
    - team1_side: str | None (attack/defense, from sides field if available)
    - team2_side: str | None

    Implementation approach:
    - Group events by round number
    - For each round, extract round_end event for scores and winner
    - Count kill events per team
    - Check for spike_plant and spike_defuse events
    - Extract sides from round_start or round_end sides field (may be None for older data)

    Handle edge cases:
    - Rounds with missing round_end (skip or mark incomplete)
    - Rounds with no kills (valid -- could be timeout or spike detonation)
    - Missing sides field (backward compatibility with pre-Phase 6 data)

    Create tests with synthetic events covering:
    - Standard round with kills, spike plant, round end
    - Round with no kills (spike detonation or timeout)
    - Multiple rounds showing score progression
    - Sides field present and absent

<task type="auto">
  <name>Task 2: Combat and side performance features</name>
  <files>src/features/extractors/combat.py, tests/features/test_combat.py</files>
  <action>
    Create `src/features/extractors/combat.py` module with combat metrics and side performance extraction.

    Functions to create:

    1. `extract_first_bloods(events: list[ValoscribeEvent]) -> dict[int, FirstBlood]`
       - For each round, identify the first kill event (lowest timestamp)
       - Return FirstBlood dataclass: round_number, killer, killer_team, victim, timestamp
       - Handle: rounds with no kills (no first blood entry)

    2. `extract_clutch_rounds(events: list[ValoscribeEvent]) -> list[ClutchRound]`
       - A clutch is when one surviving player wins the round against 2+ enemies
       - Detect by counting alive players just before final kills of the round
       - ClutchRound: round_number, clutch_player, clutch_team, opponents_remaining
       - Simplified detection: if the winning team had only 1 kill event source (1 player doing all kills) in the last N kills and the losing team had 2+ players alive at some point after, it's a clutch

    3. `extract_multi_kills(events: list[ValoscribeEvent]) -> list[MultiKill]`
       - A multi-kill is 2+ kills by the same player within 10 seconds in the same round
       - MultiKill: round_number, player, player_team, kill_count, time_window
       - Use timestamp differences between consecutive kills by same player

    4. `extract_side_performance(events: list[ValoscribeEvent]) -> SidePerformance`
       - SidePerformance dataclass: team1_attack_wins, team1_attack_rounds, team1_defense_wins, team1_defense_rounds, (same for team2)
       - Derive from round_end events with sides field
       - When sides field is None, infer from round number: R1-12 = starting sides from metadata or first available sides field, R13-24 = swapped
       - Include: attack_win_rate, defense_win_rate per team

    5. `compute_anti_eco_stats(events: list[ValoscribeEvent], economy_tiers: list | None = None) -> AntiEcoStats`
       - Track rounds where one team is on eco/light_buy and the other is on full_buy
       - Compute: anti_eco_conversion_rate (% of rounds won when opponent on eco)
       - Takes optional economy_tiers from Plan 01 (if not available, skip this feature gracefully)
       - AntiEcoStats: team1_anti_eco_wins, team1_anti_eco_rounds, team2_anti_eco_wins, team2_anti_eco_rounds

    Create tests:
    - First blood identification with timestamp ordering
    - Clutch detection (1v2, 1v3 scenarios)
    - Multi-kill detection with timestamp window
    - Side performance with known sides data
    - Anti-eco stats with mock economy tiers
    - Edge cases: no sides data, no kills in round
  </action>
  <verify>python -m pytest tests/features/test_combat.py -v</verify>
  <done>All combat extractors return correct results for test scenarios. First bloods identified correctly. Clutch and multi-kill detection works with timestamp-based logic. Side performance computes correct attack/defense rates.</done>
</task>
