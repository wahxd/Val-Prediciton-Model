<objective>
Build map-level feature aggregation and the feature registry system.

Purpose: Map-level features are what the model actually trains on -- each map produces one feature vector per team. The feature registry enables reproducible experiments by naming feature sets (e.g., "core", "economy_extended") so model training references set names, not hardcoded feature lists.

Output: `map_features.py` aggregating round/combat/economy data into map vectors, `registry.py` + `feature_sets.yaml` for named feature sets, plus tests.
</objective>

  <name>Task 1: Map-level feature aggregation</name>
  <files>src/features/extractors/map_features.py, tests/features/test_map_features.py</files>
  <action>
    Create `src/features/extractors/map_features.py` with `extract_map_features()` function that aggregates round-level data into a single feature dict per team per map.

    Function signature:
    ```python
    def extract_map_features(
        events: list[ValoscribeEvent],
        map_id: str,
        teams: list[str],  # [team1, team2]
    ) -> dict[str, Any]:
    ```

    Returns a flat dict of feature_name -> value. All features are from team1's perspective (team2 features are the inverse/complement). This is a LOCKED decision: no team identity features, purely game mechanics.

    Feature categories and names (prefix with category for clarity):

    **Score features:**
    - `final_score_team1`: int (rounds won by team1)
    - `final_score_team2`: int (rounds won by team2)
    - `score_differential`: int (team1 - team2, positive = team1 won more)
    - `total_rounds`: int
    - `went_to_overtime`: bool (total_rounds > 24)
    - `map_winner`: str (team name, the prediction target)

    **Pistol round features:**
    - `pistol_round1_winner`: str (team that won R1)
    - `pistol_round2_winner`: str (team that won R13, None if match ended before R13)
    - `pistol_rounds_won_team1`: int (0, 1, or 2)

    **Half features:**
    - `first_half_score_team1`: int (team1 rounds won in R1-R12)
    - `first_half_score_team2`: int
    - `second_half_score_team1`: int (team1 rounds won in R13+)
    - `second_half_score_team2`: int

    **Momentum features:**
    - `max_win_streak_team1`: int (longest consecutive win streak)
    - `max_win_streak_team2`: int
    - `max_loss_streak_team1`: int
    - `max_loss_streak_team2`: int
    - `comeback_from_behind`: bool (team that was behind at halftime won)

    **Combat features (aggregated from extractors):**
    - `first_blood_rate_team1`: float (% of rounds team1 got first blood)
    - `first_blood_rate_team2`: float
    - `clutch_rounds_team1`: int
    - `clutch_rounds_team2`: int
    - `multi_kill_rounds_team1`: int (rounds with at least one multi-kill)
    - `multi_kill_rounds_team2`: int

    **Side performance features:**
    - `attack_win_rate_team1`: float
    - `defense_win_rate_team1`: float
    - `attack_win_rate_team2`: float
    - `defense_win_rate_team2`: float

    **Economy features (from EconomyTracker output):**
    - `eco_round_win_rate_team1`: float (% of eco-tier rounds won)
    - `eco_round_win_rate_team2`: float
    - `avg_economy_differential`: float (mean per-round credit difference)
    - `force_buy_rounds_team1`: int (rounds where team bought despite eco-level credits)
    - `force_buy_rounds_team2`: int
    - `full_buy_rounds_team1`: int
    - `eco_rounds_team1`: int

    Implementation:
    1. Call extract_round_features() to get round-level data
    2. Call EconomyTracker to get economy data
    3. Call combat extractors for first blood, clutch, multi-kill
    4. Call side performance extractor
    5. Aggregate all into flat dict
    6. Handle missing data gracefully (None values for features that can't be computed)

    Use pandas vectorized operations where possible for aggregation (e.g., pd.Series for streak computation). BUT: since we're aggregating lists of dataclasses, plain Python loops are acceptable here -- the data is small (24-30 rounds per map).

    Create tests with synthetic map data:
    - Standard 13-7 map with known features
    - Map going to overtime
    - Map with missing economy data (should still produce score/combat features)
  </action>

  <done>extract_map_features produces correct feature dict for test maps, all feature categories populated, missing data handled gracefully</done>
