  <files>

  <action>
    Create src/modeling/thesis_validation.py with the following components:

    1. **Feature categorization** -- `categorize_features(feature_names: list[str]) -> dict[str, list[str]]`:
       Map each feature to its thesis level using keyword matching:
       - **side_map** (Level 1 - most important): Features with "attack", "defense", "half", "side", "first_half", "second_half" -- structural advantage from which side you're on
       - **pistol** (Level 2): Features with "pistol" -- winning pistols cascades into economy for 2-3 rounds
       - **economy** (Level 3): Features with "economy", "eco", "buy", "credit", "tier" (excluding pistol) -- matters after pistols
       - **momentum** (Level 4): Features with "streak", "momentum", "comeback", "overtime" -- overrated, only meaningful when already winning
       - **combat** (Level 5 - least important): Features with "clutch", "multi_kill", "first_blood", "kill" -- rare/noisy
       - **other**: Features that don't match any category (score_differential, win_rate, etc.) -- count as game mechanics but don't fit hierarchy

       Returns dict mapping category name -> list of feature names.

    2. **Hierarchy validation** -- `validate_thesis_hierarchy(feature_importance: dict[str, float], feature_names: list[str]) -> dict`:
       - Categorize all features using categorize_features()
       - Get top 10 features by SHAP importance
       - Count how many top-10 features belong to each thesis level
       - Compute average importance per level (mean SHAP of all features in that level)
       - Check hierarchy ordering: avg importance of side_map >= pistol >= economy (relaxed: only check top 3 levels)
       - Returns:
         - `level_counts`: dict of category -> count in top 10
         - `level_avg_importance`: dict of category -> mean |SHAP| for that level
         - `hierarchy_respected`: bool (side_map avg >= pistol avg >= economy avg, with tolerance)
         - `top_10_features`: list of (name, category, importance) tuples
         - `game_mechanics_pct`: % of top 10 that are ANY game mechanics (not team identity)
         - `interpretation`: human-readable string
         - `concerns`: list of specific violations (e.g., "momentum features ranked higher than economy")

    3. **Cross-tournament stability** -- `compare_feature_importance_across_groups(importances: dict[str, dict[str, float]], top_n: int = 10) -> dict`:
       - Takes dict mapping group_name (tournament) -> feature_importance dict
       - For each pair of groups, compute top-N feature overlap (Jaccard similarity)
       - Returns:
         - `pairwise_overlap`: dict of (group_a, group_b) -> overlap percentage
         - `avg_overlap`: mean overlap across all pairs
         - `stable_features`: features appearing in top-N across ALL groups
         - `unstable_features`: features appearing in top-N in some groups but not others
         - `meta_shift_detected`: bool (avg_overlap < 70% suggests meta shift per CONTEXT decisions)
         - `trading_implications`: {stable: "trustworthy for betting", unstable: "signal may expire, recommend retrain"}

    4. **Thesis report generation** -- `generate_thesis_report(hierarchy_result: dict, stability_result: dict | None = None) -> dict`:
       - Structures output following the CONTEXT pattern:
         1. **Evidence**: SHAP feature importance ranked by thesis level
         2. **Diagnosis**: Which levels dominate? Does it match hierarchy?
         3. **Thesis check**: Pass/fail with specific violations
         4. **Trading implication**: Which features are stable (trustworthy) vs meta-dependent (require retraining)
       - Returns structured dict suitable for JSON serialization

    Design per CONTEXT:
    - Thesis hierarchy is: Side x Map > Pistol > Economy > Momentum > Combat
    - 80% of top 10 features must be game mechanics (from Phase 9 validate_game_mechanics_dominance)
    - Thesis validation is testable: cross-tournament stability validates it, instability challenges it
    - "Thesis validation is more valuable than hyperparameter tuning for identifying genuine edge"
