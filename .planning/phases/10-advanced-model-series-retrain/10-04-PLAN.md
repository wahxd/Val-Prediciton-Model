  <name>Task 1: Implement Optuna XGBoost tuning and GridSearchCV logistic regression tuning</name>
  <files>

  </files>
  <action>
    Create src/modeling/tuning.py with the following functions:

    1. `tune_xgboost_optuna(X, y, groups, n_trials=100, random_state=42) -> dict`:
       - Creates Optuna study with direction='minimize' and MedianPruner(n_startup_trials=10, n_warmup_steps=5)
       - Objective function suggests hyperparameters within constrained ranges (CONTEXT: very conservative):
         - n_estimators: 30-100
         - max_depth: 2-4
         - min_child_weight: 3-10
         - learning_rate: 0.01-0.2 (log scale)
         - subsample: 0.7-0.95
         - colsample_bytree: 0.7-0.95
         - reg_alpha: 0.0-0.5
         - reg_lambda: 0.5-2.0
       - Objective: temporal holdout split (oldest 80% train, newest 20% validate) — data must be sorted by date
       - Evaluates using log_loss only (CONTEXT: ECE too noisy for n=71)
       - Returns dict with:
         - best_params: dict of best hyperparameters
         - best_log_loss: best validation log loss
         - n_trials: number of trials completed
         - study_summary: brief stats (best, worst, mean of all trials)

    2. `tune_logistic_gridsearch(X, y, groups) -> dict`:
       - Uses GridSearchCV with LeaveOneGroupOut (series_id grouping) — matches Phase 9 temporal CV
       - Parameter grid:
         - C: [0.01, 0.1, 1.0, 10.0]
         - penalty: ["l1", "l2"]
         - solver: ["saga"]  (supports both l1 and l2)
       - Scoring: neg_log_loss
       - Returns dict with:
         - best_params: dict (C, penalty, solver)
         - best_log_loss: negative of best score (converted to positive)
         - all_results: list of {params, mean_log_loss, std_log_loss} for all configs
         - n_configs: total configs evaluated

    3. `temporal_holdout_sanity_check(X, y, tuned_config: ModelConfig, default_config: ModelConfig) -> dict`:
       - Splits data temporally: oldest 80% for train, newest 20% for test
       - Trains both tuned and default models, evaluates log loss on holdout
       - Returns dict with:
         - tuned_log_loss: holdout log loss for tuned model
         - default_log_loss: holdout log loss for default model
         - improvement: tuned vs default difference
         - survives_holdout: bool (tuned beats default on holdout)
         - recommendation: "use_tuned" if survives, "use_defaults" otherwise

    4. `compare_models(xgb_cv_results: dict, lr_cv_results: dict) -> dict`:
       - Takes output from temporal_cross_validate for both models
       - Computes log_loss difference and standard error of the difference
       - Checks: XGBoost must beat LR by > 1 SE (CONTEXT decision)
       - Checks: XGBoost calibration must not degrade (max_deviation comparison)
       - Returns dict with:
         - xgb_log_loss: mean and std
         - lr_log_loss: mean and std
         - difference: XGBoost - LR log loss (negative = XGBoost better)
         - se_difference: standard error of the difference
         - significant_improvement: bool (difference > 1 SE in favor of XGBoost)
         - calibration_comparison: which model has better calibration
         - recommendation: "xgboost", "logistic_regression", or "no_clear_winner"
         - skepticism_note: string flagging whether improvement survives scrutiny

    Design per CONTEXT:
    - Log loss only as Optuna objective (Platt scaling handles calibration separately)
    - Temporal holdout: if tuned config doesn't beat defaults on holdout, tuning was noise
    - Grid search for LR is exhaustive (small grid), Optuna for XGBoost (larger space)
    - Report + skepticism: flag whether improvement over defaults survives holdout
    - Keep both models regardless (future data may change ranking)
